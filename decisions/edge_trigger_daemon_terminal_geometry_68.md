# Make daemon terminal geometry updates edge-triggered and idempotent

Status: Accepted

## Context and Problem Statement

The client-side daemon terminal called `terminal.resize` from every draw. The daemon persisted the session and broadcast `terminal.resized` for every request, including unchanged geometry, so the broadcast caused another draw and formed a self-sustaining RPC, disk-write, and redraw loop. Snapshot pulls and interactive input shared the same serialized daemon connection and could be delayed by seconds behind that traffic.

## Decision Drivers

* Interactive input must not contend with control traffic generated by rendering the same frame.
* Rendering may call `Draw` repeatedly without changing terminal geometry.
* The daemon protocol must remain safe for clients that retry or do not implement local deduplication.

## Considered Options

* Memoize the last successful geometry in the TUI adapter and make the daemon resize handler idempotent.
* Remove resize from drawing and require every caller to coordinate resize events perfectly.
* Continue accepting duplicate resize calls and prioritize input through a separate connection.

## Decision Outcome

Chosen option: "memoize client geometry and make daemon resize idempotent." The remote terminal adapter sends a resize RPC only when its requested geometry changes and records the geometry only after a successful call, preserving retry behavior after failures. The daemon independently returns the current state without touching the terminal actor, persistence file, or event stream when the requested geometry already matches its state.

### Positive Consequences

* Repeated draws do not generate resize RPCs.
* A resize notification cannot create a draw/resize notification feedback loop.
* Older or alternate clients cannot force redundant persistence and broadcasts by repeating the same geometry.
* Input and snapshot traffic no longer queue behind continuous no-op resize work.

### Negative Consequences

* The client adapter keeps a small amount of synchronized geometry state.
* A client reconnect sends one initial resize because the cache is intentionally connection-local.
